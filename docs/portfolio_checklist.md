# Product Designer Portfolio Checklist

## 🎯 Purpose
A portfolio for getting interviews at product companies in India (Bangalore). Not an art gallery - a demonstration of your problem-solving process.

---

## ✅ Essential Elements

### 1. Homepage / Landing
- [ ] Clear headline: "Product Designer specializing in [Your Niche]"
- [ ] Location: Bangalore (or "Open to relocation")
- [ ] Brief intro (2-3 sentences): Who you are, what you do, impact
- [ ] 3-4 best case studies (featured)
- [ ] Clear CTA: "View case studies" or "Get in touch"
- [ ] Professional photo (optional but recommended)
- [ ] Links to: LinkedIn, Resume (PDF), Email, Dribbble/Behance (if relevant)
- [ ] Mobile-responsive (50% of viewers on mobile)
- [ ] Fast loading (under 3 seconds)

### 2. Case Studies (3-4 high-quality)

**Each case study must have:**

#### Context Section
- [ ] Project name and company (can anonymize if NDA)
- [ ] Your role (sole designer? part of team?)
- [ ] Timeline (how long)
- [ ] Team composition (PMs, engineers, other designers)
- [ ] Platform (web, mobile, both)

#### Problem Statement
- [ ] Clear problem definition (1-2 paragraphs)
- [ ] Why this problem matters (business + user impact)
- [ ] Constraints (technical, business, time)
- [ ] Success metrics defined upfront

#### Research & Discovery
- [ ] Research methods used (user interviews, surveys, analytics, etc.)
- [ ] Key insights (3-5 bullet points with evidence)
- [ ] User personas or segments (if relevant)
- [ ] Competitive analysis (if relevant)
- [ ] Photos/videos of research process (whiteboard, interview notes)

#### Design Process
- [ ] Ideation: Sketches, wireframes, explorations
- [ ] Show alternatives considered (not just final solution)
- [ ] Design iterations (V1 vs V2 vs Final)
- [ ] Collaboration: How you worked with PMs/engineers
- [ ] Design system usage (if applicable)
- [ ] Prototypes (link to Figma/interactive prototype)
- [ ] User testing: What you learned, how you iterated

#### Solution
- [ ] High-fidelity designs (desktop + mobile if relevant)
- [ ] Key flows (annotated screenshots or flow diagrams)
- [ ] Design decisions explained (why this pattern? why this color?)
- [ ] Accessibility considerations
- [ ] Edge cases handled

#### Impact
- [ ] **Quantitative results:** Increased conversion by X%, reduced time by Y
- [ ] **Qualitative results:** User feedback, testimonials
- [ ] Business impact: Revenue, growth, retention
- [ ] What you learned
- [ ] What you'd do differently

#### Visual Quality
- [ ] Clean, professional screenshots (no pixelation)
- [ ] Consistent image sizes
- [ ] Captions for all images
- [ ] Max 15-20 images per case study
- [ ] Flow diagrams for complex interactions
- [ ] Before/after comparisons (if redesign)

---

## 📊 Case Study Formula (Structure)

```
1. Hero Image + Title (5 seconds)
   ↓
2. Quick Stats Box (15 seconds)
   - Role, Timeline, Impact
   ↓
3. Context + Problem (1 minute)
   ↓
4. Research + Insights (2 minutes)
   ↓
5. Design Process (3 minutes)
   - Sketches → Wireframes → High-fidelity
   ↓
6. Final Solution (2 minutes)
   - Key screens + flows
   ↓
7. Impact + Learnings (1 minute)
```

**Total reading time: 10-15 minutes per case study**

---

## 🎨 Case Study Topics (Choose Diverse Projects)

**Pick 3-4 from different categories:**

1. **New Feature:** Designed X from scratch, increased Y by Z%
2. **Redesign:** Improved existing feature, reduced friction
3. **Complex Flow:** Checkout, onboarding, multi-step process
4. **Mobile-First:** App design, responsive considerations
5. **B2B/Enterprise:** Dashboard, admin tools, data visualization
6. **Research-Heavy:** User research led to unexpected insights
7. **Constraint-Driven:** Technical/business constraints, creative solution

**Avoid:**
- 5 similar projects (all mobile apps or all redesigns)
- Only personal/speculative projects (need real work)
- Outdated work (older than 3 years unless exceptional)

## 🚫 Common Portfolio Mistakes

### Content Mistakes
- [ ] **No process shown** - Just final mockups (hiring managers want to see HOW you think)
- [ ] **No metrics** - "Improved UX" (by how much? says who?)
- [ ] **Fake projects** - Only redesigns of Instagram/Uber (shows you can't solve real problems)
- [ ] **NDA excuse** - "Can't show due to NDA" (then anonymize or show personal work)
- [ ] **Too much text** - Walls of text (use bullet points, visuals)
- [ ] **No context** - Jumping straight to designs (set up the problem first)
- [ ] **Generic descriptions** - "Clean, minimal, user-friendly" (be specific!)

### Visual Mistakes
- [ ] **Overcomplicated** - Too much animation, interactions (distracting)
- [ ] **Slow loading** - Large images, videos (comppress!)
- [ ] **Not mobile-friendly** - Broken on phones (test on real devices)
- [ ] **Inconsistent branding** - Different styles across projects (shows lack of attention)
- [ ] **Pixelated images** - Low-quality screenshots (looks unprofessional)
- [ ] **Too artsy** - More Dribbble shots than case studies (you're not an artist)

### Strategic Mistakes
- [ ] **No about page** - Who are you? Why should I care?
- [ ] **Outdated work** - 5-year-old projects with outdated patterns
- [ ] **No contact info** - How do I reach you?
- [ ] **Broken links** - Prototypes, external links don't work
- [ ] **No resume download** - Make it easy to save your resume
- [ ] **Password-protected** - Hiring managers won't bother (use anonymized case studies instead)

## 🔧 Technical Checklist

### Performance
- [ ] Page load time < 3 seconds
- [ ] Images optimized (use WebP format, compress)
- [ ] Lazy loading for images
- [ ] No auto-play videos (data usage)

### Responsiveness
- [ ] Works on mobile (iOS + Android)
- [ ] Works on tablet
- [ ] Works on desktop (various screen sizes)
- [ ] Test on real devices, not just emulators

### Accessibility
- [ ] Good color contrast (WCAG AA minimum)
- [ ] Alt text for all images
- [ ] Keyboard navigation works
- [ ] Screen reader friendly

### SEO (for organic discovery)
- [ ] Page titles: "[Your Name] - Product Designer Portfolio"
- [ ] Meta descriptions for each case study
- [ ] Descriptive URLs: /case-study/project-name (not /project-1)
- [ ] Schema markup for portfolio

### Analytics
- [ ] Google Analytics installed
- [ ] Track: Page views, time on page, source (LinkedIn, email, etc.)
- [ ] Use data to improve: Which projects get most views?

## 🌐 Portfolio Platforms (Recommendations)

### For Non-Coders
1. **Webflow** (Recommended)
   - Pros: Professional, customizable, fast
   - Cons: Learning curve, paid ($14/mo)
   - Best for: Custom-branded portfolio

2. **Notion** (Quick & Free)
   - Pros: Easy, fast setup, free
   - Cons: Less customizable, Notion branding
   - Best for: Quick portfolio while you build better one

3. **Adobe Portfolio** (via Behance)
   - Pros: Free with Adobe CC, clean templates
   - Cons: Limited customization
   - Best for: Adobe users

4. **Cargo** / **Format**
   - Pros: Beautiful templates, design-focused
   - Cons: Paid ($13-20/mo)
   - Best for: Visual-heavy portfolios

### For Coders
5. **Next.js + Vercel** (Free)
   - Full control, fast, free hosting
   - Requires coding knowledge

6. **GitHub Pages + Jekyll**
   - Free, simple, markdown-based
   - Basic coding needed

### Avoid
- ❌ WordPress (slow, overkill for portfolio)
- ❌ Wix (looks cheap, slow)
- ❌ Pure Dribbble/Behance (not a substitute for case studies)

## 📝 About Page Essentials

**Include:**
- [ ] Photo (professional, friendly)
- [ ] 2-3 paragraph bio
  - Who you are (background, location)
  - What you do (specialty, skills)
  - What you care about (design philosophy)
  - Fun fact (hobbies, interests - be human!)
- [ ] Skills list (be honest)
  - Design: Figma, Sketch, Prototyping, User Research
  - Other: HTML/CSS (if true), Workshop facilitation, etc.
- [ ] Tools you use (Figma, Miro, Notion, etc.)
- [ ] Contact info (email, LinkedIn, phone)
- [ ] Resume download link (PDF, always updated)
- [ ] Optional: Work history timeline, testimonials

**Don't:**
- Long life story (keep it relevant)
- Overly casual tone (you're a professional)
- Listing every tool you've touched once
- Passive voice ("I was responsible for..." → "I designed...")

## 📈 Portfolio Success Metrics

**Track these:**
- **Traffic:** How many views per week?
- **Sources:** LinkedIn, email, direct, Google?
- **Time on page:** Are people reading case studies? (Avg 3-5 mins = good)
- **Most viewed project:** What resonates?
- **Conversion:** Portfolio views → Interview requests (aim for 5-10%)

**Iterate based on data:**
- Low traffic? Improve SEO, share more on LinkedIn
- Low time on page? Content too long or not engaging
- High bounce rate on certain project? Improve that case study
- No interview requests? Ask for feedback, improve content

## 🚀 Quick Wins (If Starting From Scratch)

**Week 1:**
- [ ] Choose platform (Notion for speed, Webflow for quality)
- [ ] Write problem statements for 3 projects
- [ ] Gather screenshots, design files

**Week 2:**
- [ ] Write full case study for best project (10-15 hours)
- [ ] Create simple homepage with headline + featured project
- [ ] Add about page and contact info

**Week 3:**
- [ ] Complete 2nd case study
- [ ] Optimize images, test on mobile
- [ ] Get feedback from 3 people

**Week 4:**
- [ ] Complete 3rd case study
- [ ] Polish all content
- [ ] Launch and share!

**Minimum Viable Portfolio:**
- Homepage + 2 solid case studies + about page + contact = Ready to apply!
